# nx18 general Switch-native pipeline — current engineering branch

**First game:** Terminator 2D: NO FATE (`0100B51020B68000`).
**Fallback:** Need for Speed: Hot Pursuit Remastered (`010029B0118E8000`).
**End goal, deferred for storage:** Assassin's Creed II / The Ezio Collection (`0100670014482000`).
Target iPhone: iPhone 13 / A15 / iOS 18.7.8. **No Switch emulator, cloud streaming or JIT.**

The Windows rewriter, native framework generator and IPA packer now select their game from a verified base title ID; they reject cross-game mixes.

Development priority: finish the real native runtime, not a standalone NSP inspector.
The optional Studio inspector remains independent of the actual port.

## Real components now integrated into nx18

1. **Windows static rewriting** (`tools/rewrite_exefs.py`) invokes
   `widmonstertony/nxnative`'s actual Capstone 5 ARM64 NSO rewriter. Its
   output includes patched native images and the original fixup/gate tables.
   On Windows it forces single-worker mode because the upstream legacy fork
   assumes Unix `fork()` for parallel scans.
2. **Game code container** (`tools/build_guest18.py`) invokes the proven
   `xinerqu/ns2ios-shell` `guest_dylib.py` generator, copied and
   backported to **LC_BUILD_VERSION iOS 17.0** and a matching framework
   Info.plist. The framework holds signed Mach-O sections, *not*
   dynamically JIT-compiled ARM64.
3. **Legacy loader bridge** (`LegacyShell/NX18Guest.m`) locates the
   installed `Guest.framework/Guest`, lets dyld load its executable
   code, checks `__dm<module>x0 / __DM<module>W / __dm<module>x1`
   sections, and calls the existing legacy host function
   `dm_set_game_image_header()`. This happens **before**
   `dm_host_preload_start()`, ensuring the host's relocations and
   service gates target that signed image.
4. **Runtime profile** (`LegacyShell/apply_legacy_shell.py` backport):
   the game-specific `dm/profile.tsv` is assigned to `DM_PROFILE`
   before the legacy host selects memory sizes, guest program ID, and
   RomFS location. This avoids relying on the placeholder's defaults.
5. **Metal 3 host build** (`LegacyShell/build_shell18.sh` and
   `.github/workflows/shell18.yml`): build a reusable unsigned
   iOS 17+ shell with real nxnative host code on a GitHub-hosted Mac.
   The **user's Windows PC needs no Apple Developer downloads**.
6. **Native package assembly** (`tools/package_native18.py`): locally
   combines that host, Guest.framework, rewritten fixup/gate tables,
   a target-game runtime profile, a compatible Metal shader chain, and
   optionally RomFS into an **unsigned** IPA. The entire modified
   package and nested framework must be re-signed by the sideloader.

The legacy `nvn_mtl_legacy.inc` already has an on-device
`newLibraryWithSource` code path behind `DM_SHELL`. This is why the
backport targets Metal 3, rather than bringing the iOS 26 Metal 4 queue
into an iPhone 13 build.

## Source build, on GitHub

The [Metal3 host workflow](../.github/workflows/shell18.yml) clones the
two upstream forks, applies the bridge, invokes the legacy iOS host build,
checks Mach-O minimum OS and for forbidden iOS26 Swift runtime references,
then publishes `nx18-metal3-gamefree-unsigned.ipa` **if and only if
compilation succeeds**. Its diagnostic artifact holds the build log even
when compilation fails.

No game files, `prod.keys`, signing certificates, or user credentials are
included in the repository or GitHub Actions.

## Windows fallback, with local game files

The Windows setup script clones the real rewriter and framework generator:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-windows.ps1
python .\tools\rewrite_exefs.py "F:\Terminator\exefs" --upstream .\vendor\nxnative --title-id 0100B51020B68000 --output .\work\rewrite
python .\tools\build_guest18.py --rewritten .\work\rewrite --legacy .\vendor\nxnative --target terminator --out .\work\native
```

This presupposes your own legally extracted/decrypted ExeFS. It is **not**
a Switch-to-iPhone converter from a raw NSP yet.

When game-specific `profile.tsv`, shader map and legacy-chain shader
libraries have been generated, the offline packer accepts them and the
successful GitHub Actions host build:

```powershell
python .\tools\package_native18.py --shell .\nx18-metal3-gamefree-unsigned.ipa --guest .\work\native\Guest.framework --rewritten .\work\rewrite --profile .\Terminator\profile.tsv --shader-tables .\Terminator\shaders\tables --shaders .\Terminator\shaders\b-CHAIN --legacy-chain-header .\vendor\nxnative\dm\gfx\nvn\legacy\dmsh_chain.h --romfs .\Terminator\RomFS.img --output .\Terminator-native18-unsigned.ipa
```

`b-CHAIN` is a placeholder: it must match the actual value of
`DMSH_CHAIN` in the legacy renderer's header. The packer refuses a
mismatch. The runtime profile must be generated by upstream
`dm/games/game.py profile`, not copied directly from `game.tsv`.

All packaging stays local. Do not upload proprietary game binaries or
Nintendo keys to a public CI artifact.

## What is NOT yet verified or finished

- No confirmed **successful shell18 GitHub Actions compilation** or
  device installation is claimed in this document.
- The first-game Terminator Switch base game and update have **not yet completed**
  extracted-NCA → rewritten-NSO → shader-chain → playable IPA integration
  on the user's iPhone 13.
- A legacy NVN shader translation chain compatible with the iOS 17
  renderer must be generated and validated for Terminator (or another selected game). **Metal source
  compilation is not identical to shader translation.**
- Some Horizon service behavior, actual memory headroom, A15 BC texture
  handling, save data, audio, controller support, and frame pacing will
  need game-specific runtime tests.
- The unsigned nested-framework IPA still requires proper signing before
  iOS will allow dyld to map the game image. There is no claimed way to
  sidestep iOS code signing, no JIT, and no emulator.

The milestone after source-level loader integration is a **successful
compilation of the actual Metal3 native host**, followed by staging the
actual Terminator graphics assets and game profile—not another independent
inspection application.


## Continuation from NX18 on-device ExeFS (first automated handoff)

The iPhone extraction stage saves each decrypted ExeFS file and a
`nx18-export.json` sidecar containing the NCA title ID, filename, file size
and streaming SHA-256. No encryption keys are written to the sidecar.
Copy the **whole** export folder from the app's Files container to your
own Windows computer, then from the NX18 repository run:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\continue-native18.ps1 -ExeFS "D:\NX18\iPhoneExport"
```

This invokes setup if needed, verifies the source/title/checksums, runs the
actual upstream ARM64 NSO rewriter, and creates the iOS 17 Guest.framework.
The results are under `work\native-from-phone\rewrite` and
`work\native-from-phone\native` with `pipeline-report.json`.

For older extracted folders without a sidecar, specify the known game's
title ID explicitly: `-TitleId 0100B51020B68000`.

**Important limitation:** iOS does not allow a sideloaded app to load
arbitrarily generated unsigned native code. The Windows process builds
native game code, not a directly launchable IPA. ROMFS, legacy Metal 3
shader translation, packaging and full nested code signing remain distinct
later gates. No game files should be committed to a public repository.
